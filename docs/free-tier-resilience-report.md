# Free-tier resilience implementation report

1. **Calls found before the refactor.** `answer.ts` final synthesis; `rerank.ts` optional AI reranking; `tagging.ts` ambiguous batch classification; `candidate-claims.ts` chunk claim/event/relationship proposals. All used `gemini.ts`, which could call both `models.generateContent` and `interactions.create`. `embeddings.ts` called `models.embedContent` for query and explicit corpus embeddings; `live-research/cache.ts` automatically ran corpus embeddings after page fetches. Full purpose, frequency, caching, timeout and failure map: [model-usage-audit.md](model-usage-audit.md).

2. **Removed calls.** Removed the Interactions second attempt, interactive model reranking, SDK/application embedding retries, and automatic embedding enrichment during live-page caching. Routing, pronouns, expansion, sufficiency and citation checking already used code; no fictitious removed routing model is claimed.

3. **Remaining calls.** Optional Gemini final synthesis provides natural interpretation of bounded evidence. Explicit background tagging and candidate extraction provide ambiguous classification/proposals, with checkpoints. Explicit embeddings and sparse-candidate query embeddings improve vector recall. Optional AI reranking remains available only to explicit callers supplying `allowModel: true`; Ask never does so. No new vendor or dependency was added.

4. **Normal Ask call limit.** Zero or one generative API attempt per request, enforced by request-local AsyncLocalStorage. SDK retry attempts are one. Comparisons share that same request budget. Successful cached synthesis, extractive mode, open circuits and deterministic abstention use zero generation calls.

5. **Routing.** Selected personality/category, database `routing_hints`, framework codes and known database term aliases drive deterministic routing. An additive migration fills the requested vocabulary for texts, tapas, lineage, relationships, chronology, contested identity and contemporary relevance. Broad questions intentionally retrieve across parameters. Independent claims, lexical/cached passages, inventory, registry and approved event/relationship support queries run concurrently, each with measured latency. Structured proposals never contribute unreviewed descriptions: only approved records' active approved supporting source passages enter retrieval.

6. **Pronouns/context.** Singular references resolve against one selected personality outside quoted text. Unambiguous `their` also resolves; bounded named-entity history supports plural follow-ups. Aliases are read from personality/research-term registries; punctuation and numeric references remain intact. Responses expose small structured context: active IDs, recent entities, topic and parameters. Large conversation histories are not sent to synthesis.

7. **Answer cache.** Separate server-only Supabase `answer_cache`, 24-hour expiry, SHA-256 identity, exact conservative case/whitespace/trailing-question-mark normalization. Fresh retrieval and sufficiency precede every cache read. Only citation-valid generated answers are cached; fallback excerpts do not prevent later provider recovery. Hits update access time/count atomically. A cache/storage outage becomes a miss without breaking Ask.

8. **Invalidation.** Identity includes personality scope, policy, ordered evidence content and provenance, supporting source approval metadata and citation payload. Changed/revoked evidence changes the key or fails current sufficiency. Live passages must remain unexpired and authorized by current approved active URL scopes. Linked rejected/unapproved sources cannot supply cached claim evidence. Numeric references and internal punctuation are not collapsed into potentially different questions. No semantic answer reuse is enabled.

9. **Provider interface.** `SynthesisProvider` defines configuration, grounded generation and error classification. `GeminiSynthesisProvider` and `ExtractiveSynthesisProvider` implement it. Retrieval is independent of provider implementation. Existing environment variables remain supported; new neutral settings include `SYNTHESIS_PROVIDER`, `SYNTHESIS_MODEL`, `SYNTHESIS_TIMEOUT_MS`, plus `SYNTHESIS_DISABLED` and `EMBEDDINGS_DISABLED` test controls. No provider secrets are public.

10. **Errors.** Code classifies quota/resource-exhausted, rate limit/429, timeout, authentication/configuration, unavailable model/404, transient 5xx/network and invalid response. Wrapped causes are inspected. Normal users receive evidence or abstention, not raw provider errors. Generation timeout defaults to 8 seconds and is capped at 12 seconds; embeddings abort at 3.5 seconds. There is no retry chain or second fact-checker call.

11. **Circuit.** In-process generation and embedding circuits: quota/rate/config/model errors cool down for 60 seconds; transient/timeout/invalid responses for 15 seconds. Calls resume afterward; a successful response resets the circuit. Tests verify first 429 → cited fallback, next request → no model attempt, cooldown expiry → retry allowed. These are process-local circuits, not distributed coordination.

12. **Extractive fallback.** Actual excerpts, deduplicated and bounded to 500 characters, with preserved citation IDs and source/type/layer metadata. Broad views group up to six categories; focused views show up to five excerpts. UI status is `extractive_fallback` and labels the result “Verified evidence view”; generated responses are labeled “AI-generated synthesis.” Unknown/grouped fabricated citations or entirely uncited generated answers trigger fallback. Valid grouped citations render as individual inspectable source buttons. The previous local prose helper remains available for compatibility, but Ask uses the new verbatim renderer.

13. **Embedding failure.** Claims/FTS/metadata/cached approved passages continue. `semanticFallbackReason` reports a safe classified reason. Semantic search intentionally follows local candidate counts, so ordinary supported questions avoid query embedding quota. No embeddings are required to boot or answer questions. Tests cover query failure with a useful lexical answer.

14. **Approved live research.** Works without generative AI. Real Aurobindo benchmark testing fetched an approved PDF, parsed it and cached 603 additional source chunks without generation or embedding calls. A Next.js native-package configuration fix repaired its PDF worker resolution. Reranking then included modern and primary textual layers, and the question returned a cited extractive response. Subsequent requests use the cached passages. Oversized IGNCA PDFs remained blocked at the existing 12 MB limit. URL scopes, redirects, DNS/SSRF checks and RLS remain enforced. The mocked full Ask test separately verifies fetch → cache → reretrieve → extractive response in one request.

15. **Background ingestion.** Server-only `ai_work_checkpoints` records input/model hashes, status and saved output per chunk/batch. Output is saved before applying proposals; interrupted application reuses it. States include processing/complete/failed_quota/failed_transient/failed_permanent. Tagging stores deterministic results before optional AI, then saves each classified batch. Candidate extraction scans past completed units and processes a bounded number of new units. Embedding batches save output and stop at provider failure; completed vectors are skipped on resume. Re-run the same action/plan after cooldown. Onboarding stops further AI enrichment while circuits are open; deterministic work remains possible. Explicit admin jobs should not run concurrently for the same source; this does not introduce a distributed queue or lock service.

16. **Real “Who is Vishvamitra?” with available synthesis.** Passed after live testing exposed and corrected Gemini's rejection of HTTP deadline headers below ten seconds. The short timeout is now enforced by AbortSignal instead of that header. Real Gemini result: `complete`, 12 citations, one generative call, zero embeddings, 9233 ms including retrieval; a normalized repeat returned the persisted synthesis in 1143 ms with zero generative calls and `answerCacheHit=true`. Automatic approval review initially blocked the external-payload test; the user authorized continuation and the approved test then ran successfully. [resilience-live-provider-results.json](resilience-live-provider-results.json).

17. **Same question, unavailable synthesis.** Real production test with `SYNTHESIS_DISABLED=true EMBEDDINGS_DISABLED=true`: grouped approved evidence, inspectable citations, zero generative/embedding calls. Initial acceptance sample: 1094 ms, 12 evidence citations.

18. **Rama role, unavailable synthesis.** Real cited excerpts cover his guiding Rama/Lakshmana, journeys, Siddhashrama, Bala/Atibala and weapons. Initial disabled-production acceptance: 999 ms, 15 evidence citations, zero generative/embedding calls.

19. **Favorite food, unavailable synthesis.** Correct evidence-based abstention; zero citations and zero generative/embedding calls. Initial disabled-production acceptance: 2738 ms, including bounded approved live attempts that could not supply sufficient evidence. Additional unsupported height/algebra/America questions are covered in the full benchmark. Subject relevance prevents unrelated whole-book live passages from masquerading as biographical support.

20. **First/repeated request.** Real Gemini Ask: first successful broad answer makes one model call and persists cache; normalized repeat hits cache with zero generation (9233 → 1143 ms). Changed-evidence cache invalidation is verified in orchestration tests. Real disabled mode deliberately does not persist excerpts as synthesized answers, so uncached local repeats render evidence with zero generation. The live Rama synthesis timed out after the eight-second application limit and returned cited extracts; the favorite-food question abstained without a model call. That timeout opened the provider circuit while the broad-question cache continued to serve its valid generated answer.

21. **Before/after calls.** Before: default local mode zero; opted-in generation one successful API attempt, potentially two on failure, plus optional reranking calls and up to three embedding attempts. After: normal Ask at most one generation attempt, no interactive reranker, no automatic live-page embeddings, one attempt per requested query embedding. Routing, pronouns and citation validation remain zero-call code paths.

22. **Measured latency.** Three alternating warm samples against the same linked Supabase corpus: broad-question median 1332 ms baseline → 997 ms current; Rama-role median 3762 ms baseline (abstained) → 1076 ms current (cited evidence). Baseline was an unchanged committed snapshot in a temporary production server with local synthesis; current samples used the development server. Network variation and concurrent benchmark traffic make these observational samples, not a controlled performance guarantee. No invented before-change Gemini latency is reported; actual current Gemini/cache timings appear in items 16 and 20. Raw samples: [resilience-latency-samples.json](resilience-latency-samples.json).

23. **Automated results.** 102 tests pass across 13 files, up from 58 passing tests across 11 files; all original tests preserved. Final real Vishvamitra corpus benchmark: 25/25, including supported and unsupported questions. [resilience-benchmark-results.json](resilience-benchmark-results.json). New tests include provider budgets/abstraction, quota/cooldown/recovery, abort timeout, aliases/pronouns, cache matching/invalidation, parallel retrieval, local extracts/grouping, citation rejection, embedding failure, no-synthesis live flow, revoked live authorization and checkpoint resume.

24. **Checks/migrations.** Typecheck, ESLint and webpack production build pass. Both additive migrations were applied to the linked Supabase project and local/remote histories match: `20261003010000_add_resilient_ai_caches` and `20261003020000_complete_deterministic_routing_hints`. Cache/checkpoint tables use RLS and service-role-only access. No corpus data was destroyed and no secrets are committed.

25. **Remaining Gemini dependence.** Optional natural synthesis, query/corpus embeddings, explicit ambiguous tagging/proposal extraction, and explicit offline model reranking. Core ingestion, deterministic tags, search, approved live lookup/fetch/cache, citations, evidence views and abstention operate without it. Usage counters are process-local and reset on restart; they do not include personal identity or external analytics.

26. **Local URLs/reproduction.** `http://localhost:3000/ask`, `/corpus`, `/corpus/onboard`, `/corpus/sources`; API `POST http://localhost:3000/api/ask`. Dedicated disabled-provider production test server is running at `http://127.0.0.1:3002/ask`. Run `CORPUS_API_BASE=http://127.0.0.1:3002 node scripts/resilience-acceptance.mjs`. Final rebuilt-server acceptance passed: broad cached synthesis 1500 ms, Rama extractive evidence 1108 ms, favorite-food abstention 3010 ms, normalized broad cache hit 1178 ms; every request used zero generation and embedding calls. Disabled providers still permit safe reuse of previously generated cached answers. For the approved provider-enabled test, set `RESILIENCE_EXPECT_PROVIDER=gemini` and point the same script at a provider-enabled server. No credential deletion is needed.

27. **Commit.** The final response records the exact commit hash; `git rev-parse HEAD` identifies it locally. The live Gemini synthesis/cache test, mocked quota/cooldown tests, provider-disabled application checks and implementation checks have passed.
